# 批量照片风格转换

用此技能管理可重复执行的照片风格转换。每一轮都必须从已指定的**原图文件夹**开始，除非用户明确要求叠加转换，否则绝不能把上一轮风格图当作下一轮输入。

## 隐私与外部处理边界

1. 用户的原图和提示词一旦交给 `imagegen`，会由内置图片生成服务处理。用户要求“仅本地处理”、不希望将照片交给生成服务，或原图不适合外发时，只能做本地的去元数据、归档与裁切，不能调用图片生成。
2. 对包含人像、地点、设备信息，或计划分享结果目录的任务，默认加 `--privacy-mode`。该模式不在归档中保留完整提示词、绝对路径、原始文件名、风格标签或时间，并将建议输出名改为 `image-001.png` 这类匿名名称。隐私模式需要使用单独的结果父文件夹，不能与已有的普通归档混用。
3. 调用 `imagegen` 前，先在权限为 `0700` 的临时目录中创建去元数据副本：使用可信的 ImageMagick 执行 `-auto-orient -strip`，只把副本交给图片生成服务。随后检查副本、生成图片，并删除该临时目录。不得把本机用户名、绝对路径、联系方式或无关私密信息写进模型提示词。
4. `--prompt-file` 仅用于安全地传入提示词。若该临时文件由本轮任务创建，在归档完成后删除它；不要把完整提示词作为命令行参数传入。
5. 不跟随原图文件夹中的符号链接。若确实需要处理链接目标，先让用户明确说明原因与目标范围。

## 建立图片集合

1. 确定原图文件夹、风格结果的父文件夹，以及用户的完整提示词。如果当前对话里的“这个文件夹”指向明确，直接采用；否则只问一个简短问题来确认路径。若风格结果父文件夹中已有 `collection.json`，读取其中记录的 `source_folder` 作为原图基准。
2. 检查原图文件夹，只统计该目录第一层的图片文件（`.jpg`、`.jpeg`、`.png`、`.webp`、`.heic`、`.tif`、`.tiff`、`.avif`），不要递归扫描风格结果子文件夹。
3. 保护原图：未经明确要求，不得改名、删除、覆盖原图，也不得用上一轮结果作为下一轮输入。
4. 从提示词提炼一个简短、可读的目录标签，例如 `搞怪蜡笔涂鸦` 或 `照片与黑白手绘双画面`。

在生成前先创建本轮目录，并归档原图清单与完整提示词：

```bash
python3 <技能目录>/scripts/create_run_folder.py \
  --source-dir "<原图文件夹>" \
  --style-name "<本轮风格短名称（可省略，默认“风格转换”）>" \
  --prompt-file "<保存完整用户提示词的 UTF-8 文件>" \
  --output-parent "<风格结果父文件夹>" \
  --privacy-mode
```

只有需要隐私归档时才在命令末尾保留 `--privacy-mode`；普通归档可省略。隐私模式下建议省略 `--style-name` 或使用通用标签，脚本只打印“已创建私密归档目录”，避免在终端回显本机路径。用安全的文件写入方式创建提示词文件，绝不能把用户提示词直接插入 Shell 命令。普通归档时脚本会打印新建的本轮目录，例如 `02-照片与黑白手绘双画面`。

## 生成常规风格图

1. 每张原图都是独立的编辑目标。若输入只存在于本地文件系统，先用 `view_image` 检查每张已去元数据的临时副本，再调用内置图片生成器。普通任务也应优先使用去元数据副本；用户明确要求保留元数据时，必须说明这一取舍。
2. 使用 `imagegen` 技能的内置编辑流程，每张原图单独调用一次图片生成。除非用户明确要求，否则不要切换到 CLI/API 备用流程。
3. 把用户提示词放在最前面，完整保留其约束；只补充让模型理解为“编辑任务”所需的最少上下文：

   ```text
   用途：照片风格转换
   成品类型：归档用的个人照片风格转换
   输入图片：这张原图是唯一的编辑目标
   主要请求：<用户的完整提示词>
   约束：保留用户指定的人物身份、服装、姿势、物品、构图和背景等不变量；除非用户要求，否则不要增加人物、宠物或文字。
   ```

   如果提示词已经足够详细，只做结构化整理，不要增加会与其冲突的新创意。如果用户请求新场景、合成或重新摆姿势，必须明确说明哪些图片是身份参考，哪一张是编辑目标。
4. 将选定的最终图复制到本轮目录，统一使用稳定的图片扩展名（通常为 `.png`）。原图文件名主干唯一时用 `<原图主干名>.png`；若两张原图的主干名相同，则用 `<原图主干名>--<原始扩展名>.png`，例如 `portrait--jpg.png` 与 `portrait--png.png`。辅助脚本会在 `run-manifest.json` 中预先计算不冲突的输出名。不得覆盖已存在的最终图；用户要求再次尝试时，才使用版本后缀。
5. 普通归档中创建 `outputs.json`，记录每个原图文件名、对应的输出文件名，以及有针对性的重试记录。隐私模式只能记录匿名编号与匿名输出名，不能写入原文件名映射。保留辅助脚本创建的 `Prompt.txt`、`run-manifest.json` 与集合级 `collection.json`；隐私模式下这些文件不会包含完整提示词或绝对路径。
6. 确认最终图数量等于原图数量。逐张目检人物主体、身份特征、物体数量、构图与风格是否满足要求；只对失败的图片做有针对性的再次编辑。

## 双画面海报模式

当用户请求上下结构、前后对照、照片与插画对照，或其他双画面海报时，使用此模式。

1. 仍按常规风格图流程归档。若用户要求严格双画面，在每一条生成提示中都明确目标比例、画面顺序、上下占比，以及上半部分照片必须保留的全部不变量。
2. 只生成用户要求的画面数量。不要把双画面变成拼贴、增加额外相框，也不要让大标题遮住主体。
3. 若某个分区必须保留原照片，要明确写它是对原图的编辑，而不是重新设计；准确限定允许的调整，例如“只做轻微高级感调色”。
4. 接受结果前，检查分隔线与上下比例。若原图涉及身份保留，每张海报都要检查五官、发型、衣服、姿势和主体数量。

## 拆出双画面中的单个分区

当用户要求从完成的海报中单独拆出上半或下半图时，使用确定性裁切，不要再次调用图片生成模型。

1. 检查有代表性的海报，确定真实分隔线。只有上下确实等高时才用 `--split-ratio 0.5`；若分隔线位于固定像素行，用 `--split-y`，不要猜测。
2. 将拆出的图片保存到新的命名子文件夹，例如 `下半部黑白手绘单图`。裁切默认会自动校正方向并清除 EXIF、GPS、XMP、IPTC 与缩略图元数据；只有用户明确要求时才传入 `--preserve-metadata`，且该选项不能与 `--privacy-mode` 一起使用。目标文件夹非空时，裁切脚本会拒绝覆盖；明确提供 `--overwrite` 后，脚本会清理先前裁切出的图片并重建该集合。
3. 对布局一致的一批海报，运行：

   ```bash
   python3 <技能目录>/scripts/extract_diptych_panel.py \
     --input-dir "<海报本轮目录>" \
     --output-dir "<海报本轮目录>/下半部黑白手绘单图" \
     --panel lower \
     --split-ratio 0.5 \
     --privacy-mode
   ```

   拆上半部时改为 `--panel upper`。仅在需要匿名命名和匿名清单时保留 `--privacy-mode`。脚本只做像素裁切，不会让模型重新绘制，并会写入包含裁切几何信息的 `crop-manifest.json`。
4. 验证每个拆出的文件都存在，且尺寸与预期相符。若不同海报的分隔线不同，分别用正确的 `--split-y` 裁切，不能对整批图片套用错误的统一裁切。

需要更多双画面与裁切检查时，参阅 [双画面与裁切检查](references/diptych-and-extraction.md)。

## 完成后的汇报

汇报原图文件夹、新建的本轮目录、成功保存的图片数量，以及任何需要重试的结果。给用户提供最终文件夹的直接链接。只要使用过生成式模型，就不要宣称人物身份或像素级保留绝对准确；如有可见限制，应如实说明。
