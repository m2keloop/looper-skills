# 热股排行与每日复盘口径

本 Skill 观察各比赛官方当次返回的截断热股榜，不是全部股票或全部参赛者持仓。默认 `--hot-only` 不采集逐人持仓、不计算金额分档权重；加权分析须显式选择 `--capital-groups` 并具备完整数据。

## 排行与名单

按 `market + stock_code` 匹配证券，名称只用于展示。报告及 `contests.csv` 保留当次查询过的比赛名称、分享 key、官方参与人数、入选与采集状态，以及源时间。参与人数严格大于阈值才入选；每次以实际查询为准。

| 字段 | 含义 |
|---|---|
| `contest_count` | 股票进入官方热榜的比赛数 |
| `holder_count_sum` | 这些比赛官方 `hold_num` 之和 |
| `rank` | 保存的主榜名次；默认优先比赛覆盖数，再按人数合计 |
| `weighted_consensus_score` | 完整四档可用时的加权共识分，否则为 `null` |
| `contests` | 支撑该股票统计的比赛及各自人数、名次和源时间 |

同一个人可能参加多场比赛，合计人数**未经跨比赛去重**，不能称为独立投资者人数。HTML 支持表头升降序、比赛覆盖、持仓人数等排序；四档可用时增加加权共识排序。临时界面排序不改写保存的主榜名次及跨日差，缺失值置于末尾。

## 完整四档加权

配置为 `data/consensus-weights.json`，默认新手/十万/百万/千万组权重 **1/2/3/5**，代码为 `1/10/100/1000`。四档权重必须为有限正数、各不相同，千万组严格最高；改变数值时同时改变版本号。

```text
共识分 = 官方热榜持仓人数合计
       + Σ((该档权重 − 1) × 该档公开持仓人数)
```

此分数混合官方汇总和逐人公开持仓两种观测来源，不是精确分组总人数、去重人数或资金金额。只对本次原官方热榜范围计数，不能将未上榜股票的持仓填为零。

加权校验要求所有入选比赛四组名单和公开持仓读取完整，成功读取数等于成员数、失败数为零，记录不重复且覆盖原热榜；每个持仓人数不得超过该组成员数。四组公开持仓人数之和若高于同场股票的官方热榜人数，视为来源或时点口径不一致，停止加权。完整同步失败保留上次报告；独立分析无效补采时分数保持 `null`，不得拼凑部分分数。

## 比较基线与每日变化

基线取更早日期、最近一次完整且口径兼容的快照，**未必就是昨天**。报告标明基线日期；排除同日、未完成以及 `threshold/scope/stock_scope/selection_rule` 不同的快照。四档模式优先采用可用的完整分组历史；明确失败补采不能替代有效的分组基线。没有可用基线时是首次建档，变化为缺失，不能写成零。

在两期共同入选比赛内，按同一比赛、市场和股票比较：

| `change_type` | 情况 | 持仓人数差 |
|---|---|---|
| `changed` | 两期均上榜，人数或名次等可观察字段变化 | 本次减基线 |
| `unchanged` | 两期均上榜，可观察字段不变 | `0` |
| `new_hot_list` | 本次上榜、基线未上榜 | `null` |
| `exited_hot_list` | 基线上榜、本次未上榜 | `null` |

榜内名次差为基线名次减本次名次，正数表示上升。JSON 缺失值为 `null`，CSV 为留空；入榜与退出不把未知人数当作零。原始分组人数变化只在两期均完整且股票在同场两期均上榜时计算，按档分别展示。

比赛跨越人数阈值或发现新比赛时，单列入选、退出及参与人数变化。比赛样本不同则停算全体综合名次和合计人数跨日差，只比较共同比赛内记录。某股票合计人数差还要求它两期覆盖的比赛集合相同。

加权主榜名次和分数差进一步要求两期四档完整、**权重版本与数值相同、比赛样本相同**；该股票分数差还要求覆盖的比赛集合相同。排序口径从汇总切到加权或反向切换时，不比较综合主榜名次差。权重改变不能改写原始持仓人数。

入榜、退出、人数变化不能直接解释为买入、卖出或加仓；无可观察变化也不能证明没人交易。

## 报告和离线复盘

完整报告位于 `WORK_DIR/reports/<date>/<run_id>/`，包括 `analysis.json`、`hot-stock-ranking.csv`、`contests.csv`、`changes.csv`、`daily-review.md` 和 `index.html`。报告根目录的 `latest.json/index.html` 指向最新完整报告；`sync-latest.json/sync-history/` 记录最近任务，即使它休市跳过或失败。不要把旧完整报告当作新任务成功。

用随包公开聚合样例离线演示，不访问网络、不受交易日限制：

```sh
python3 "$SKILL_DIR/scripts/sync_hot_contests.py" \
  --analyze-only --hot-only \
  --snapshots "$SKILL_DIR/assets/sample-snapshots" \
  --report-root "$WORK_DIR/reports"
```

样例包含 2026-10-09 和 2026-10-10 两轮真实热榜聚合，只用于演示，**不代表最新数据**。分析自己的历史快照时，替换 `--snapshots`；需要指定某轮可添加 `--snapshot "$WORK_DIR/snapshots/<run_id>"`。报告继续使用快照日期，不改成执行日期。

## 可选日 K 线观察

`review_hot_stock_klines.py` 从分析排行中选持仓人数合计前 10 只 A 股，剔除 ETF 等基金，读取腾讯公开前复权与不复权日线，保存 `review.json/candles.json/index.html`。默认会联网，至少 2 秒串行访问；传入 `--candles` 则只读取已有缓存，不访问网络。随包样例的完整离线命令见 [SKILL.md](../SKILL.md)，不得用旧样例冒充本次行情。

涨幅使用前复权收盘，涨停形态候选使用不复权涨幅及收盘接近最高价；成交量指标 VR20 为最新成交量除以前 20 个交易日成交量中位数。涨停候选是近似形态，受除权、历史风险警示状态和新股规则影响，不是官方涨停统计，更不能证明参赛者在板上买入。必须注明实际最后交易日期、取得时间和来源。`assets/sample-candles.json` 为历史字段样例，不能当作自动刷新结果。
