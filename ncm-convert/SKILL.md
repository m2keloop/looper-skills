# NCM 音乐转换

按顺序完成：检测系统并选择程序 → 获取待转换路径 → 执行转换并核验结果。用户仅要求创建或修改本 Skill 时，不启动音乐转换。

## 1. 检测运行环境

使用本 Skill 所在目录的 `bin/`，不要依赖原始 Downloads 目录或当前工作目录。下文 `<skill-dir>` 必须替换为实际绝对路径。

在 Unix 系统用 `uname -s` 和 `uname -m`，在 Windows 用 PowerShell 的 `[System.Runtime.InteropServices.RuntimeInformation]::OSArchitecture` 并确认操作系统。检测的是实际执行命令的主机，不能只根据用户电脑或文件名猜测。

| 系统与架构 | 随附程序 |
| --- | --- |
| macOS / Darwin，arm64（Apple Silicon） | `bin/ncmdump-mac` |
| Linux，x86_64 | `bin/ncmdump-linux` |
| Windows，X64 | `bin/ncmdump-win.exe` |

这三份程序由用户提供，macOS 版不是 Intel 通用版本。遇到其他架构，停止转换并说明需要对应架构的程序；不要盲目运行、自动安装模拟器或替换程序。

检查程序存在，Unix 下如仅缺少执行权限，可对选中的程序执行 `chmod u+x`。运行所选程序的 `--help` 验证可启动及支持的参数。遇到动态库缺失、系统安全拦截或执行失败时，报告具体错误；不要自动移除系统隔离属性或关闭系统保护。

## 2. 获取待转换路径

如果用户尚未提供输入路径，询问：“需要转换的 .ncm 文件或文件夹在哪里？请提供完整路径，也可以直接拖入文件或文件夹。”等待回答后继续。用户已经提供清晰路径时直接使用，不重复询问。不要把 Skill 自带的三个程序误认为待转换文件。

检查路径存在且可读；单文件必须是 `.ncm`（扩展名不区分大小写）。支持用户明确选择的多个文件。

文件夹默认只处理当前层；用户明确要求包含子文件夹时才递归。执行前统计范围内 NCM 数量，没有匹配文件则告知并结束。

默认输出到源文件所在目录，保留原始 NCM。用户指定输出目录则使用 `-o`。用户要求的目标路径超出工具写入权限时，按实际执行环境申请权限。

执行前为整批输入建立“原始文件 → 最终输出路径”映射，并去重重复选择的同一源文件。默认使用原目录；多个文件统一指定 `-o` 时使用输出目录加源文件 basename；文件夹递归加 `-o` 时保留相对输入根目录的层级。未知内部音频格式时，为每个输入同时预留同名 `.mp3` 和 `.flac` 两种目标。

按目标文件系统的路径等价规则检查已有文件和批内重复目标，包括大小写不敏感目录中的大小写差异。不确定大小写规则时按不区分大小写保守检查。发现冲突先列出涉及的源文件和目标路径：已有文件询问覆盖或换目录；不同源文件映射到同一目标时，询问使用独立子目录还是不同文件名。只换一个公共空目录不能解决批内重名。解决后重新检查整批映射，再开始转换；每份输入都应有独立结果。

## 3. 执行转换

先简短说明转换数量、是否递归和输出位置，再运行命令。用户提供路径后即继续其已请求的转换，无需另问“是否开始”。

Unix 示例（实际运行时替换绝对路径并正确引用）：

```sh
"<skill-dir>/bin/ncmdump-mac" "/absolute/path/song.ncm"
"<skill-dir>/bin/ncmdump-mac" "/absolute/path/a.ncm" "/absolute/path/b.ncm"
"<skill-dir>/bin/ncmdump-mac" -d "/absolute/path/music"
"<skill-dir>/bin/ncmdump-mac" -d "/absolute/path/music" -r -o "/absolute/path/output"
```

Linux 替换为 `ncmdump-linux`。Windows PowerShell 使用调用运算符：

```powershell
& '<skill-dir>\bin\ncmdump-win.exe' 'C:\Music\song.ncm'
& '<skill-dir>\bin\ncmdump-win.exe' -d 'C:\Music' -r -o 'C:\Converted'
```

把用户路径作为独立参数传入；处理引号、空格和特殊字符，不把文件名拼接为可执行的 shell 代码。

随附程序会静默跳过扩展名不是严格小写 `.ncm` 的文件，直接逐文件传入 `.NCM` 也无效。对 `.NCM`、`.Ncm` 等文件，为每个源文件创建独立临时目录，将其复制为保留原 basename、扩展名改为 `.ncm` 的临时文件，不重命名原文件。对临时副本逐文件执行，并显式用 `-o` 指向上一步映射中的最终目标目录，不能让音频留在临时目录；递归场景同样按原文件的相对目录映射输出。若用户选择了不同输出文件名，临时副本使用该目标 basename。

文件夹批处理中，严格小写输入可正常处理；其余扩展名单独走临时副本流程，按原始输入列表核对数量，不能依赖 `-d` 覆盖它们。临时副本调用不传 `-m`；核验最终音频后清理本次创建的临时目录，失败时也仅清理这些临时文件，保留原文件并报告失败。用户明确要求成功后删除源文件时，必须在最终音频核验成功后对原始文件执行删除，不能把删除临时副本当作完成该请求。

`-r` 必须配合 `-d`。`-o` 与递归搭配会保留目录结构，冲突检查应按此结构进行。默认不传 `-m` / `--remove`；只有用户明确要求成功后删除源文件时才使用。

输出格式由 NCM 内部音频决定，可能为 MP3 或 FLAC，不能承诺全部输出 MP3。用户明确要求统一 MP3 时，先说明该程序不提供强制转码参数，单独确认是否需要追加音频转码流程。

保存退出码与程序输出，并检查预期的新音频文件存在且非空；不要仅凭退出码声称全部成功。报告成功数量、失败或跳过数量和输出目录，必要时列出失败文件及错误。未实际转换或未能核验的项目明确说明。不要无条件重试整个批次。
